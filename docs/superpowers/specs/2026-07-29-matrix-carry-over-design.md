# Eisenhower Matrix:未完成任務跨週延續

日期:2026-07-29
狀態:已與使用者確認設計
分支:從 `main` 開新分支

## 背景與問題

上一個功能([2026-07-28-matrix-week-scope-design.md](2026-07-28-matrix-week-scope-design.md))讓 Matrix 按週分期,解決了歷史區無限累積的問題。但實際使用後暴露一個更嚴重的 UX 問題:

**週次一翻過去,上週沒完成的任務就從畫面上消失了**,使用者必須手動往回翻週次才找得到它們。任務並沒有做完,卻被藏起來——這正是上次程式碼審查預警過的「被困在未造訪週次的任務沒有入口」。

## 使用者決策(已確認)

1. **未完成任務自動跟到本週**:只要沒勾完成,任務就持續出現在目前檢視的象限裡,不需往回翻。Matrix 的定位是「還沒做完的事」看板。
2. **往回翻時象限一樣顯示全部未完成**:象限內容不隨週次變動;週次箭頭只控制下方已完成區(那一週完成了什麼)。
3. **方案**:後端把週窗只套用在已完成任務,一次查詢回傳全部。

## 設計

### 1. 後端查詢條件(server/db.ts `getUserTasks`)

現行條件:

```
dueDate 在週窗內  OR  dueDate IS NULL
```

改為:

```
completed = false  OR  completedAt 在週窗內  OR  completedAt IS NULL
```

語意:未完成任務不受週窗限制(它們是待辦看板的內容);已完成任務出現在**它被完成的那一週**;沒有完成時間的舊資料維持每週可見(避免任務消失的保護)。

已完成任務以 `completedAt`(而非 `dueDate`)分週,是實作期間審查發現的必要修正:`dueDate` 是任務**建立**的那一週,若沿用它,一個延續數週後才完成的任務會在勾選當下同時從象限與已完成區消失——正是本功能要消滅的「任務憑空不見」的翻版。以 `completedAt` 分週也讓已完成區名副其實地回答「這一週我完成了什麼」。

未傳 `weekStart` 時(Work/Life、Admin)完全不套用週窗,行為不變。

循環任務的虛擬列**維持現狀不動**:它們沒有 `quadrant` 欄位,本來就不會出現在 Matrix;Work/Life 不傳日期,走的是既有的 90 天路徑。改動它只會製造無使用者可見效果的churn。

### 2. 前端排序(client/src/pages/EisenhowerMatrix.tsx `tasksByQuadrant`)

現行排序為「先 `dueDate`、再 `order`」。過去同一週的任務 `dueDate` 相同,所以實際等同只看 `order`。改動後象限會混入不同週的任務,`dueDate` 會升為主要排序鍵,導致**跨週拖拉排序無法生效**(放開後彈回原位)——與先前修掉的「樂觀更新無效」屬同一類問題。

因此象限排序改為**只依 `order`**;`order` 相同時維持伺服器回傳順序(SQL 已是 `ORDER BY order ASC, createdAt DESC`,而 `Array.prototype.sort` 穩定,故並列項目保持 createdAt 遞減)。

`order` 值原本是各週各自從 0 編號,混合後會有重複。真正防止碰撞的是建立時的行為改動(見下方 Fix 2):新任務一律取該象限現有未完成任務的 `max(order)+1`,而非每天各自從 0 起算;若只靠拖拉重新編號,下一週的新建任務仍會從 0 重新開始,碰撞會再次發生,無法自行收斂。

### 3. 已完成區週別標示(client/src/components/matrix/CompletedSection.tsx)

象限不再隨週次變動後,週次箭頭實際上只影響已完成區。若無提示,使用者按箭頭會以為功能失效。已完成區標題加上該週範圍:

```
已完成（3）· 07/27 - 08/02
```

日期格式沿用頁面既有的 `MM/DD` 呈現方式。無已完成任務時仍顯示週範圍,讓「這週還沒完成任何事」一目了然。

### 4. 測試

- **後端整合測試**(server/tasks.test.ts,延續既有的週窗測試檔):
  - 未完成任務(dueDate 在上一週 / 本週 / 下一週)→ 查詢任何一週都**必須**回傳
  - 已完成 + completedAt 在上一週 → 查詢本週時**不得**回傳;查詢它那一週時必須回傳
  - 已完成 + completedAt 正好等於週起始 → 必須回傳;正好等於週起始 +7 天 → 不得回傳(釘住半開區間)
  - 沒有 completedAt 的任務 → 每週都回傳
  - 不傳 date → 全部回傳
  - 每個條件分支都必須有對應 fixture:刪掉述詞中任一分支,測試都要失敗
- `server/weekWindow.test.ts` 不動(週窗計算本身未變)。
- dev 環境(port 4179)實測:上週未完成任務出現在本週象限;跨週任務可互相拖拉排序且重整後保持;已完成區標題顯示正確週範圍。

## 取捨

未完成任務會持續累積在象限中,不因週次推進而消失。這是使用者明確選擇的行為,代價是象限可能愈來愈長,清理需靠完成或刪除。本次不實作自動封存或數量上限(YAGNI)。

`tasks(userId, category, dueDate)` 目前沒有索引,而未完成任務的查詢集合會隨時間單調增長(carry-over 讓舊任務持續留在結果裡)。現有規模下無影響,但值得記錄,供未來規模變大時參考。

## 不做的事

- 不修改任務的 `dueDate`(不做資料層的「搬移到本週」)。
- 不加「延續自 X 週」的來源標記(使用者已否決)。
- 不動 Work/Life 頁與循環任務邏輯。
- 不做象限任務數量上限或自動封存。
